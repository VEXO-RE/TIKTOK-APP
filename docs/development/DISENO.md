# Diseño de producto

Propuesta para fases 4–6, no diseño ya aprobado.
Entregables: docs/design/DESIGN.md con identidad real, tipografía, color, espaciado y tokens semánticos; inventario de componentes/pantallas; estados loading/empty/error/disabled; captura real para QA.

Calendario muestra zona/conflictos. Review identifica cuenta, snapshot y destino. Media muestra versión/derechos/QC. Jobs distingue preparado, aprobado, Inbox y publicado.
No botón Publish que solo hace Upload. Editar archivo/cuenta/CTA invalida aprobación. Errores con próxima acción, no secretos ni infraestructura en la UI.
Vista previa debe mostrar el mismo hash que se enviará.

Datos/activos propios verificados; sin placeholders comerciales, testimonios, ratings, stock o precios falsos.
Accesibilidad con contraste medido, teclado, foco y nombres de controles. Subtítulos/transcripción según medio. Respetar reduced-motion.
Tokens de timing/easing configurables, no reglas de TikTok. Safe areas se comprueban contra la UI real, sin medidas inventadas.
No reemplazar framework por apariencia premium. Usar Stitch para explorar tokens/pantallas y Figma opcional para colaboración.
Comprobar conexión real antes de confiar en disponibilidad. Ver SKILLS-PLUGINS.md.
Gate: QA móvil/escritorio, fuente de texto/datos y reproducción/acción real; mockup no certifica backend.
Referencia primaria: [WCAG](https://github.com/w3c/wcag).
